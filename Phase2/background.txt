# 游戏描述

## 给 AI 的前置描述（Prompt Preamble）

### 第一部分：游戏是什么

```
《Boxy》是一款手机端的打破第四面墙的休闲解谜平台跳跃游戏(cozy puzzle platformer)。

玩家操控一个小盒子造型角色，通过屏幕下方的左/右/跳跃按钮移动，
每关的目标是从起始门到达终点门。

这款游戏的核心设计哲学是：
游戏画面中你所看到的一切——UI按钮、提示文字、关卡编号、
甚至加载界面和系统设置——都可能是谜题的一部分。
它们可以被拖拽、被点击、被破坏、被赋予物理属性、
或者其文字含义本身就是解谜的线索。
解密的最终方式往往是反直觉的，如同脑经急转弯
```

### 第二部分：一个"好的 Boxy 关卡"必须满足的设计原则

```
设计一个 Boxy 关卡时，必须同时满足以下五条原则：

【原则 1：复用，不发明】
  谜题应当尽可能利用游戏中"已经存在"的元素来构建，
  包括：左/右/跳跃按钮、暂停/重置/提示三个系统UI、
  起始门/终点门、提示文本、关卡编号牌、钥匙与锁、
  箱子、平台地面等。
  不要凭空引入玩家从未见过的新机制或新UI
  （如对话框、新按钮类型），
  除非该关卡的核心就是"这个元素第一次以意外方式出现"。

【原则 2：意外但合理的翻转】
  每个关卡的核心体验是一个"认知翻转"——
  玩家基于游戏常识做出的第一反应是错的，
  但正确答案在事后回想时必须让人觉得"确实应该这样"。
  翻转必须有逻辑支撑，不能是纯粹的随机或无厘头。

  常见的翻转类型包括：
  - UI 越界：UI元素获得物理属性（碰撞/重力/可拖拽）
  - 语义双关：提示文字的字面含义就是解法（如提示“unity is strenght”其实解法是拖动"Unity"这个词去砸敌人）
  - 规则颠覆：破坏游戏自己建立的规则（如打烂红绿灯取消红绿规则）
  - 视角/空间欺骗：屏幕外存在隐藏区域，或"失败动作"（跳下悬崖）反而通向正解
  - 系统层利用：利用音量设置、加载界面等"游戏外"的东西来解谜
  - 预期反转：看起来像陷阱/失败的操作，实际上是唯一的通关方式

【原则 3：路径短】
  解谜的核心步骤应该控制在 2～3 步。
  一旦玩家"想通了"，执行起来应该非常简单直接。
  复杂度在于"想到"，而不在于"做到"。

【原则 4：提示语即谜题的一部分】
  每关都有一句提示文本。
  这句话不是简单的说明文字，
  它应当同时具备以下一种或多种功能：
  - 表面含义误导玩家走向错误方向
  - 隐含双关/暗示指向真实解法
  - 提示文本本身在物理上可以被交互（拖拽/破坏/当平台）

【原则 5：关卡之间有节奏和递进】
  好的关卡序列应当：
  - 先用简单关卡教会玩家一个交互模式（如"钥匙开锁"）
  - 后续关卡颠覆这个模式（如"钥匙是假的，直接拖走锁"）
  - 再后续关卡在颠覆的基础上再叠加新的变化
    （如"锁会飞走、翅膀才是关键道具"）
  同一个元素可以在不同关卡中扮演完全不同的角色。
```

### 第三部分：一个好关卡的结构范式

```
一个典型的 Boxy 关卡由以下四层构成：

┌─────────────────────────────────────────┐
│  【表层】玩家看到了什么                      │
│  场景布局 + 提示文字 → 引导出一个"显而易见"的解法思路 │
├─────────────────────────────────────────┤
│  【误导层】为什么"显而易见"的路走不通            │
│  假线索（假钥匙/假门/够不到的道具/无尽的路径）     │
│  利用了玩家的某种惯性认知                      │
├─────────────────────────────────────────┤
│  【翻转层】真正的解法藏在哪里                   │
│  某个"不该被交互"的元素其实可以被交互            │
│  或者某个"正常功能"的元素被赋予了新用途           │
├─────────────────────────────────────────┤
│  【反馈层】玩家如何知道自己做对了/做错了          │
│  探索反馈 → 渐进反馈 → 成功/失败演出            │
└─────────────────────────────────────────┘
```
